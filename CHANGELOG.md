# Changelog

All notable changes to Decor4All are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

`2.0.0` is the port release — 1.18.2 (Fabric only) → 1.21.11 / 26.1 / 26.2 /
26.3 (Fabric and NeoForge) — and it is **breaking**. Nothing about it is
remotely backwards compatible with `1.2`, by decision: the namespace rename
alone re-keys every block, item, recipe, tag, loot table and lang entry.

This file is a draft until the in-game checklist in `TODO.md` is worked
through; the technical record behind every entry below is `PORTING_PLAN.md`
(§11.2 for the runtime breaks, §15 for the shipped fixes) and `HANDOVER.md`.

## [2.0.0] - Unreleased

### Added

- Minecraft **1.21.11, 26.1, 26.2 and 26.3**, each on **Fabric and NeoForge**
  (eight loader projects; one jar per minor line). 1.18.2 was Fabric-only.
- **45 new blocks**: the cherry, mangrove and pale oak families, 15 blocks per
  wood (bench ×3, chair ×2, stool, table, fence, fence gate, stripped
  variants), taking the registry from 121 to **166 blocks**. All three woods
  exist on every supported target, so no content is version-gated.
- **166 recipes** generated by the checked-in `DataProvider`: 165 recipes of
  type `decor4all:carpenter_table` plus the carpenter table's own shaped
  crafting recipe, with an unlock advancement. The handler implements
  `RecipeBookMenu`, so the carpentry table opens on a populated, scrollable
  recipe book.
- **NeoForge support**, behind one loader seam (`ContentRegistrar` /
  `VersionCheckRegistrar`), with classtweaker-based access widening on every
  target (no access wideners anywhere).
- A **play-phase version ping** (`decor4all:version_check`, integer
  `PROTOCOL_VERSION`) that disconnects a mismatched client with a translated
  message, replacing the 1.18.2 login-phase handshake.
- **Modded axe support on log benches**: acceptance is
  `stack.is(ItemTags.AXES) || item instanceof AxeItem`, so a tagged item that
  is not an `AxeItem` and an untagged `AxeItem` both store.
- Block-entity renderers for the stored axe, one per loader, with slot state
  synced to the client (`getUpdatePacket`/`getUpdateTag`) so the axe appears
  without a chunk reload.
- A conditional suppression mixin for the stray
  "Height limit for building is 319" mount overlay (26.1, 26.2 and 26.3 only —
  1.21.11 has no such bug). The only mixin in the tree.
- CI: a `diff -r` parity gate that fails on any divergence outside the
  sanctioned exclude set, `prismDoctor`, and jar upload with
  `if-no-files-found: error`.
- Generator assertions wired into `main`: registry-vs-file coverage (166
  blockstates, 166 item definitions, 166 loot tables, 166 recipes, 170 lang
  keys) and resolution of every non-vanilla `parent`/`model`/`texture`
  reference against both the generated and hand-authored trees.

### Changed

- **BREAKING — the mod id was renamed `decor4fabric` → `decor4all`.** Every
  block, item, recipe, tag, loot table, creative-tab key and lang entry moved
  with it. 1.18.2 worlds, saves and datapacks do not resolve against the new
  ids and are explicitly out of scope (see Migration notes).
- **BREAKING — `decor4fabric:workbench` became
  `decor4all:carpenter_table`**, along with its recipe type, serializer, menu,
  screen, textures and lang key. The recipe itself was redesigned from
  `blue_dye + paper + logs` to `paper + iron_ingot + planks`.
- The workbench recipe no longer extends `CuttingRecipe` (that class was
  removed upstream in 1.20); `decor4all:carpenter_table` is now a standalone,
  codec-based `SingleItemRecipe` with a modern ingredient shape.
- The stored axe is no longer an `axe_type` blockstate property: 22 bench
  blockstates lost their 24 axe variants each, the axe models and
  `*_rot`/`*_rot_mir` textures are gone, and the block entity renderer draws
  the axe instead. Storing or retrieving an axe no longer rotates the bench
  (`FACING` is written only at placement).
- Version comparison is an integer protocol check, not
  `Float.parseFloat(modVersion)`.
- Resource JSON is generated rather than hand-maintained: 815 hand-written
  files became 1176 generated files per tree, byte-identical across 1.21.11 /
  26.1 / 26.2 (26.3 differs only in its sanctioned unlock advancement).
- Creative tab contents are ordered by a display list separate from
  registration order, so cherry, mangrove and pale oak read inline with the
  other woods instead of being stranded at the bottom of each tab.
- License metadata now reads `cc-by-nc-sa-4.0` everywhere. `LICENSE` and
  `README.md` always said CC BY-NC-SA 4.0; `fabric.mod.json` was the file that
  disagreed.

### Fixed

These are the breaks that a green build, a full jar and a clean headless
server did **not** prove fixed — grouped by how they surfaced. Sources:
`PORTING_PLAN.md` §11.2, the traps in `HANDOVER.md`, the shipped fixes in §15.

Load-time and datapack:

- **Loot tables were written to `data/<ns>/loot_table/<id>.json` instead of
  `data/<ns>/loot_table/blocks/<id>.json`.** The `blocks/` segment is
  load-bearing since 1.21.2, so every block broke into nothing in survival
  while models, items and creative tabs all rendered fine. The generator's
  coverage assertion checked the same wrong path it wrote.
- **The carpenter table dropped nothing** — 1.18.2 shipped no loot table for
  `workbench` at all (§1.4 item 3); `decor4all:carpenter_table` now drops
  itself.
- **All 165 carpentry recipes were dropped at datapack load**: 1.18.2's
  `{"item": "minecraft:oak_log"}` ingredient object no longer parses —
  `Ingredient.CODEC` takes a bare id, a bare `#tag`, or an array of those.
- **The recipe directory is `recipe/`, not `recipes/`** — the plural spelling
  exists nowhere in modern vanilla, which would have opened an empty grid.
- **The recipe type landed in `minecraft:`**: `RecipeType.register("name")`
  does not namespace, so every generated file's `decor4all:carpenter_table`
  type failed to resolve. The serializer had the same flaw on 1.21.11 (and on
  26.x it has no `register` helper at all), and an unregistered serializer is
  invisible until load.
- **Duplicate `MenuType` registration** crashed mod init (`MenuType.register`
  both constructs *and* registers under `minecraft:`); the widened
  `MenuType(MenuSupplier, FeatureFlagSet)` constructor also needs an explicit
  classtweaker entry or javac calls it private.
- **NeoForge: `RegisterClientCommandsEvent` was registered on the mod bus.**
  It fires on the main game bus on every supported version; on the mod bus it
  passes compile and kills construction at startup.
- **26.3: the recipe-unlock advancement used the old `recipe` condition
  key** — 26.3 renamed it to `recipes`, failing datapack load on the first
  boot.
- Carried over from 1.18.2 and fixed while reading the old tree rather than
  running it: the misnamed `oak_acacia_log_chair*.json` recipe files (the only
  producers of the oak chair recipes — deleting them as duplicates makes both
  chairs unobtainable), and 16 dead files under `temporary recipes/`
  referencing an unregistered serializer.

GUI (found only by opening the screen and clicking):

- **Every click returned `cell = -1`**: `isHovering` takes a rect *relative*
  to `leftPos`/`topPos`, but 1.18.2's took absolute coordinates, so the origin
  was subtracted twice and the hit test never matched — while the list
  rendered perfectly.
- **The list drew a pixel high**: a recipe cell is 18px tall but an item is
  16px, and vanilla insets the frame (`y + 1`) and the item (`y + 2`)
  differently.
- **The scrollbar was immobile**: vanilla uses three different origins
  (hit-test `+9`, draw `+15`, drag `+14`) and a literal `41.0F` offset, not
  `track - thumb`; scrolling is per *row* (`ceil(count/4) - 3`), a list that
  fits must not scroll at all, and `mouseClicked` must never write the scroll
  position — only `mouseDragged`/`mouseScrolled` may. The disabled thumb
  otherwise jumps to the cursor and cannot be moved back.
- **The GUI background rendered nothing on 1.21.11**: `blit`'s
  pixel-coordinate overload was replaced by a normalised-UV one, so the old
  argument list compiled with `u1 = v1 = 256` and sampled off the texture.

Port defects found after the build was green:

- Item definitions pointed at `minecraft:item/<id>` instead of
  `decor4all:item/<id>` (missing item models), and `benchParent(int)` was off
  by one so `_bench_2`/`_bench_3` inherited the wrong model.
- **Placing a seat while looking straight down crashed** —
  `getNearestLookingDirection()` can return `UP`/`DOWN`, which a four-value
  horizontal `FACING` property cannot hold; replaced by
  `Direction.fromYRot(...)` (`PlacementFacings`).
- **16 textures were never emitted** (12 axe overlays, the workbench's three
  top/bottom textures and the GUI background), producing a missing-texture
  warning per axe variant on every boot. Now unrepeatable:
  `assertReferencesResolve` fails the build instead.
- **`LogFenceGateBlock`'s codec hard-coded `WoodType.OAK`** — wrong wood for
  ten of the eleven gates; the override is deleted and the vanilla
  `FenceGateBlock` codec (which carries `wood_type`) is inherited instead.
- **Seat occupancy leaked**: `Sit` inserted with integer block coords but two
  of the three removal paths used different key spaces, so any removal that
  was not a passenger dismount (chunk unload, dimension change, `/kill`) left
  the seat permanently "occupied". Replaced by an occupancy blockstate; the
  seat is released on dismount, chunk unload and dimension change.
- **The version-mismatch message rendered literally** as
  `Please install Decor4All1.2 for Minecraft x to play on this server.` — the
  `String.format` had no format specifiers. Now a per-call translated
  component.
- The `Sit` callback was re-registered on every sit (three blocks called
  `sitMain()` from `onUse`), accumulating handlers for the process lifetime.
- Two independent `AXE_TYPE` blockstate properties shared one name, and
  `Sit` statically imported one and read it from both — load-bearing luck,
  since `BlockState.get` resolves by property name. Collapsed to one
  constant (and the property itself is gone since the axe renderer landed).
- The stray "Height limit for building is 319" overlay around mounting —
  diagnosed as vanilla-derived and cosmetic (`startRiding` teleports the
  rider, and the only `sendBuildLimitMessage` call site with no height test
  fires while the teleport ack is pending), hidden by the conditional mixin.

### Removed

- **1.18.2 as a target**, with it Yarn mappings, Loom, Java 17 and the
  Fabric-only build.
- **The `decor4fabric:workbench` id** (renamed, not dropped — see Migration
  notes).
- **1.18.2 world compatibility.** The id rename makes old saves, datapacks
  and `/give` macros stop resolving; this was last released years ago and
  supporting them is out of scope (`PORTING_PLAN.md` §5.1).
- **The login-phase version lock**: `ServerLoginNetworking`/`ClientLoginNetworking`
  channels, the `Float.parseFloat` version compare and
  `Sit.INCORRECT_VERSION`.
- **The `axe_type` blockstate property** and everything that existed only to
  serve it: 12 generated axe models per version, 6 hand-authored
  composite/parent models, and the 12 `<axe>_rot`/`<axe>_rot_mir` textures.
- **16 dead recipe files** under `temporary recipes/` (type
  `decor4fabric:workfence` was never registered) and the empty, never-called
  `itemRegistry`.
- **Unused 1.18.2 assets**: six base `<axe>.png` item textures and
  `data/decor4fabric/icon.png`, none referenced by any model.
- The `CuttingRecipe` superclass dependency (`grep -rln "CuttingRecipe"
  versions/` returns nothing).
- **The `/decor4all axe` client dev command** (`AxePose`, `AxePoseCommand`
  and their Fabric/NeoForge registrations), a debug-only helper for eyeballing
  the bench axe pose. The renderer keeps its own pose constants.
- **Build tooling from the shipped jars.** The resource `generator` package
  moved out of `src/main` into its own `src/generator` source set, so the
  registry-poking datagen code and `IntrusiveHolderAccess` no longer compile
  into the released jar. `./gradlew generateResources` is unchanged for
  contributors; the committed `src/main/generated/resources` trees are
  byte-identical.
- The orphaned `textures/gui/container/carpenter_table.png` (referenced by no
  model or screen).

### Migration notes

From `1.2` (Minecraft 1.18.2, `decor4fabric:`) to `2.0.0` (Minecraft 1.21.11
/ 26.1 / 26.2 / 26.3, `decor4all:`):

1. **Namespace rename: `decor4fabric:` → `decor4all:`.** This is a breaking
   world-compat change with no automatic remapping. It affects blocks, items,
   recipes, recipe types, tags, loot tables, advancements, creative-tab lang
   keys and every `block.*`/`item.*` translation key. A 1.18.2 world's blocks
   will not resolve; edit NBT/datapacks by hand or start a new world.
2. **One block id also changed path: `decor4fabric:workbench` →
   `decor4all:carpenter_table`.** Its recipe
   (`decor4fabric:workbench` → `decor4all:carpenter_table`), menu, screen,
   textures and lang key (`block.decor4fabric.workbench` →
   `block.decor4all.carpenter_table`) moved with it.
3. **The other 120 block ids keep their exact path under the new namespace**,
   in the same relative order — e.g. `decor4fabric:oak_log_chair` →
   `decor4all:oak_log_chair`, `decor4fabric:crimson_stem_bench` →
   `decor4all:crimson_stem_bench`. The `_log_`/`_stem_` asymmetry between
   overworld woods and nether woods is preserved, not normalised. 45 ids are
   appended (cherry, mangrove, pale oak); nothing is interleaved.
4. **Creative tab keys**: `itemGroup.decor4fabric.seats|tables|fences` →
   `itemGroup.decor4all.seats|tables|fences`, plus the new
   `container.decor4all.carpenter_table`. The carpenter table item now sits
   in vanilla's `minecraft:functional_blocks` tab, because 1.18.2's
   `ItemGroup.DECORATIONS` no longer exists.
5. **Data directories follow vanilla's renames**: `data/decor4fabric/recipes/`
   → `data/decor4all/recipe/` (singular),
   `data/decor4fabric/loot_tables/blocks/` → `data/decor4all/loot_table/blocks/`,
   `data/minecraft/tags/blocks/` → `data/minecraft/tags/block/`. Custom
   datapacks copying the old paths must be re-pathed.
6. **Removed ids**: none beyond `workbench`. The 16 dead
   `temporary recipes/` files referenced a serializer that was never
   registered, so their outputs were never obtainable in the first place.
7. **Multiplayer**: version compatibility is now checked by a play-phase ping
   using an integer `PROTOCOL_VERSION` rather than at login. A mismatched
   client is disconnected with a translated message after the world starts
   loading, instead of being rejected before it.
8. **License metadata** is `cc-by-nc-sa-4.0` (CC BY-NC-SA 4.0) in every
   built jar. It was always the stated license in `LICENSE`/`README.md`;
   only the mod metadata disagreed with it in `1.2`.
